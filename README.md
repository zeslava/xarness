# xarness

[Русский](README.md) | [English](README.en.md)

xarness — простой harness с самым необходимым для работы с кодом.

Цель проекта — выжать максимум пользы из модели за минимум токенов.

Возможности:

- OpenAI-совместимый Chat Completions API: с локальным сервером, например llama.cpp, или удалённым API
- Чтение и поиск по файлам, навигация по определениям, редактирование и запуск shell-команд, в том числе в фоне.
- Карта репозитория и инструкции из `AGENTS.md` в контексте модели.
- Сохранение диалогов, продолжение сессий и сжатие истории при заполнении контекста.
- Переключение моделей и настроенных уровней рассуждения прямо в диалоге.
- Подключение MCP-серверов, LSP-навигация, skills и собственные субагенты.

## Установка

```bash
curl --proto '=https' --tlsv1.2 -sSf https://raw.githubusercontent.com/zeslava/xarness/main/install.sh | sh
```

Скрипт определяет ОС и архитектуру (Linux x86_64/aarch64, macOS arm64), скачивает последний релиз, проверяет контрольную сумму при наличии `shasum` или `sha256sum` и ставит бинарник в `~/.local/bin`. Убедитесь, что этот каталог есть в `PATH`. Другой путь — через `INSTALL_DIR`:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://raw.githubusercontent.com/zeslava/xarness/main/install.sh \
  | INSTALL_DIR=/usr/local/bin sh
```

Для сборки из исходников нужен Rust с поддержкой edition 2024:

```bash
cargo install --path .
```

## Быстрый старт

1. Запустите OpenAI-совместимый сервер с моделью, поддерживающей вызов инструментов (tool calling). В примере сервер уже доступен по адресу `http://127.0.0.1:8080/v1`.
2. Создайте `~/.config/xarness/config.json`:

   ```json
   {
     "default": "local/my-model",
     "providers": {
       "local": {
         "base_url": "http://127.0.0.1:8080/v1",
         "models": [
           { "id": "my-model" }
         ]
       }
     }
   }
   ```

   `default` задаётся в формате `{provider}/{model_id}`: `local` — имя провайдера (ключ в `providers`), `my-model` — значение `id` в его списке `models`. Замените `my-model` в обоих местах на идентификатор модели, который принимает ваш сервер. Ключ для локального сервера без авторизации не нужен.

3. Перейдите в каталог проекта и запустите агент:

   ```bash
   cd /path/to/project
   xarness
   ```

4. Введите задачу, например: `Найди причину падения теста и исправь её`. Для предварительного разбора используйте `/plan <задача>`: агент исследует код и предложит план; изменения и запуск команд в этом ходе требуют подтверждения.

При запуске без конфигурации xarness пытается создать `~/.config/xarness/config.json` с пустым `providers` и открывает интерфейс с подсказкой. Добавьте провайдера и модели, затем перезапустите приложение.

Каталог запуска становится рабочим корнем: чтение, запись и редактирование файлов снаружи требуют подтверждения. Shell-команды запускаются из этого каталога и также требуют подтверждения; это не изоляция процессов на уровне ОС. Обычные правки файлов внутри проекта применяются без отдельного запроса.

## Конфигурация

Поддерживаются JSON и TOML; все примеры ниже используют JSON. Настройки читаются при запуске и объединяются в следующем порядке:

| Слой | JSON | TOML |
| --- | --- | --- |
| Глобальный, на всех ОС | `~/.config/xarness/config.json` | `~/.config/xarness/config.toml` |
| Настройки проекта | `./.xarness/config.json` | `./.xarness/config.toml` |
| Локальные настройки проекта | `./.xarness/config.local.json` | `./.xarness/config.local.toml` |

В каждом слое используется только первый существующий файл: JSON имеет приоритет над TOML. Создавайте новые конфигурации в JSON; TOML поддерживается для совместимости. Более поздний слой переопределяет предыдущий по ключам. Объекты объединяются рекурсивно, массивы заменяются целиком: например, новый `models` заменит весь список моделей провайдера.

Общие настройки проекта можно хранить в `.xarness/config.json`, а личные адреса и ключи — в `.xarness/config.local.json`. Добавьте `.xarness/config.local.*` в `.gitignore` своего проекта. После изменения настроек перезапустите xarness.

### Провайдер и модель

Пример для удалённого API; замените адрес и идентификатор модели на значения своего сервиса:

```json
{
  "default": "remote/my-model",
  "auto_compact": 0.8,
  "providers": {
    "remote": {
      "kind": "openai",
      "base_url": "https://api.example.com/v1",
      "api_key_env": "XARNESS_API_KEY",
      "models": [
        {
          "id": "my-model",
          "name": "Основная модель",
          "context_window": 32768,
          "max_tokens": 4096,
          "temperature": 0.2
        }
      ]
    }
  }
}
```

Перед запуском задайте `XARNESS_API_KEY` в окружении. Вместо `api_key_env` можно указать `api_key` напрямую; если заданы оба, приоритет у `api_key`.

| Параметр | Назначение |
| --- | --- |
| `default` | Модель при запуске в формате `провайдер/id`. Без него выбирается первая модель первого по алфавиту провайдера с непустым списком `models`. |
| `providers.<имя>.kind` | Тип API; сейчас поддерживается `openai`, он же используется по умолчанию. |
| `base_url` | Префикс API. xarness добавляет к нему `/chat/completions`, поэтому полный путь к этому методу указывать не нужно. |
| `models` | Явный список доступных моделей: автоматически с сервера не загружается. |
| `id` / `name` | Идентификатор модели для API / необязательное отображаемое имя. |
| `context_window` | Размер контекста в токенах для подгонки истории. Указывайте реальный размер контекста сервера. |
| `max_tokens` | Лимит токенов ответа, передаваемый серверу. Без него поле не отправляется. |
| `temperature` | Необязательная настройка случайности ответа. |
| `auto_compact` | Доля заполнения контекста, после которой история сжимается по завершении хода; без настройки выключено. Можно задать глобально или у модели, где значение имеет приоритет. |

В идентификаторе модели могут быть `/`: например, `remote/org/model` означает провайдера `remote` и модель `org/model`. Переключение в интерфейсе: `/model remote/my-model`; `/model` показывает список.

Если `context_window` не задан, xarness пытается получить `n_ctx` из `/props` сервера llama.cpp перед каждым ходом. Если это не удалось, история отправляется без подгонки под размер окна. Для других серверов размер контекста лучше задать явно.

### Уровни рассуждения

Параметр `think` задаётся у провайдера или модели. Модель наследует настройку провайдера, если не задала собственную. Доступные уровни показывает `/think`, переключает — `/think <уровень>`.

Для API с полем `reasoning_effort` добавьте в объект провайдера или модели поле `think`:

```json
{
  "think": {
    "default": "low",
    "levels": ["low", "high"]
  }
}
```

Также принимается короткая форма `"think": ["low", "high"]`, без выбора уровня по умолчанию. Для шаблонов llama.cpp с переключателем `enable_thinking` есть пресет `"think": "qwen"` с уровнями `on` и `off`.

Произвольные поля запроса можно описать явно. Например, вместо пресета добавьте в объект провайдера `local` следующее поле `think`:

```json
{
  "think": {
    "default": "off",
    "levels": {
      "on": {
        "chat_template_kwargs": { "enable_thinking": true }
      },
      "off": {
        "chat_template_kwargs": { "enable_thinking": false }
      }
    }
  }
}
```

Поля выбранного уровня объединяются с телом запроса как JSON. Их поддержку определяет ваш сервер и модель.

### MCP

MCP добавляет агенту инструменты внешних серверов. Для каждого сервера задайте либо `command` для stdio, либо `url` для Streamable HTTP. Ниже шаблоны: замените путь, аргументы и URL на параметры своего MCP-сервера.

Добавьте объект `mcp` на верхний уровень конфигурации:

```json
{
  "mcp": {
    "local_tools": {
      "command": "/absolute/path/to/mcp-server",
      "args": [],
      "env": { "EXAMPLE_SETTING": "value" },
      "approval": "auto"
    },
    "remote_tools": {
      "url": "https://mcp.example.com/mcp",
      "headers_env": { "Authorization": "MCP_AUTHORIZATION" },
      "approval": "always"
    }
  }
}
```

В `headers_env` задаётся имя переменной окружения с полным значением заголовка, например `Bearer …`. Обычные заголовки можно указать через `headers`.

- `"approval": "auto"` (по умолчанию) — подтверждать инструменты, не помеченные сервером как read-only.
- `"approval": "always"` — подтверждать каждый вызов.
- `"approval": "never"` — не запрашивать подтверждение в обычном ходе.
- `"tools": ["tool_name"]` — предоставить только перечисленные инструменты сервера; без списка доступны все.
- `"enabled": false` — отключить сервер.

Серверы подключаются в фоне при запуске. `/mcp` показывает их состояние и список доступных инструментов с описаниями, сгруппированный по серверам. Инструменты доступны модели под именами `сервер__инструмент`; эти же имена показаны в списке. При заданном `tools` отображаются только разрешённые инструменты.

### Языковые серверы (LSP)

Укажите установленные stdio-серверы явно; xarness не ищет и не устанавливает их:

```json
{
  "lsp": {
    "rust": {
      "command": "rust-analyzer",
      "filetypes": { "rs": "rust" }
    },
    "go": {
      "command": "gopls",
      "filetypes": { "go": "go" }
    }
  }
}
```

Объект `lsp` использует обычные слои конфигурации. Поля сервера: `enabled` (по умолчанию `true`), `command`, `args`, `env`, `filetypes` (расширение без точки → идентификатор языка), `initialization_options` и `settings`. Например, для gopls можно задать `"settings": { "gopls": { "staticcheck": true } }`. Два включённых сервера для одного расширения — ошибка конфигурации.

При наличии включённого LSP-конфига модель получает два read-only инструмента:

- `find_usages`: семантические ссылки без объявления символа.
- `goto_definition`: переход к определению символа.

Оба принимают путь к файлу `path` и ровно один вариант адресации: `name` (одно точное имя определения, в том числе квалифицированное, например `Type::method` или `Type.method`) либо `line` и `column` (с единицы, столбец в Unicode-символах). Поиск по имени использует определения `read_symbol`; при неоднозначности возвращаются кандидаты. Для языков без поддержки tree-sitter используйте позицию. Результаты сортируются и очищаются от дубликатов: максимум 50 местоположений с явным сообщением об обрезке, окружающим определением, когда оно доступно, и одной строкой контекста. Для результатов вне рабочего корня содержимое не читается; столбцы отмечаются кодировкой сервера.

Сервер запускается при первом запросе. Соединение общее для пары «сервер, рабочий корень инструментов»: субагенты с тем же корнем разделяют его, с другой директорией используют отдельный workspace. Allowlist инструментов субагента сохраняется: добавьте `find_usages` и/или `goto_definition` для разрешения навигации. Входные пути вне корня требуют подтверждения.

Перед навигацией открытые документы сверяются с диском и синхронизируются с возрастающими версиями. Зарегистрированные сервером файловые watchers доставляют события создания, изменения, удаления и переименования через инструменты, shell-команды и внешние редакторы. Таймаут инициализации — 30 секунд; навигация имеет отдельный общий таймаут 30 секунд на ожидание готовности, запрос и повторы при смене снимка workspace. Для rust-analyzer клиент запрашивает `experimental/serverStatus` и ждёт `quiescent: true`; у остальных серверов учитываются активные progress-операции, но универсальной гарантии завершения индексации нет. Если загрузка началась во время запроса, результат запрашивается заново после её завершения. Отмена инструмента отменяет его запрос и сохраняет сервер; после падения следующий вызов подключается заново. Ошибки соединения, загрузки workspace, неподдерживаемые возможности, таймауты и успешный пустой результат различаются; автоматического текстового fallback нет. Ход работы и предупреждения о неполной работоспособности сервера отображаются в результатах и `/lsp`.

`/lsp` показывает соединения, возможности, ход работы, последнюю ошибку и ограниченный лог stderr. Серверные запросы применения правок отклоняются. Диагностика, hover, рефакторинг и иерархия вызовов в эту версию не входят. MCP, карта репозитория, `grep` и `read_symbol` работают независимо; подключение и падение сервера не меняют схемы инструментов и не перестраивают карту.

Для тестов используется управляемый stdio-сервер на Python 3. Дополнительная проверка с установленными rust-analyzer, gopls и обоими toolchain:

```bash
cargo test real_language_servers -- --ignored --nocapture
```

### Инструкции проекта и skills

Поместите правила работы с проектом — команды проверки, соглашения, ограничения — в `AGENTS.md` в каталоге запуска. Файл читается при старте и добавляется в системный промпт. Поиск в родительских и вложенных каталогах не выполняется.

Skills — повторно используемые инструкции в файлах `<имя>/SKILL.md`. Каталоги поиска, по приоритету:

1. `./.xarness/skills/`
2. `./.agents/skills/`
3. `~/.config/xarness/skills/`
4. `~/.agents/skills/`

При совпадении имени используется первый найденный skill. Пример `.xarness/skills/review/SKILL.md`:

```markdown
---
name: review
description: Проверить изменения на ошибки и пропущенные проверки
---
Изучи git diff, найди возможные ошибки и укажи файлы и причины.
```

Пользователь вызывает skill через `/review [задача]`, модель может загрузить его по описанию. `/skills` показывает каталог. Встроенный `/plan` доступен без файлов; собственный skill с именем `plan` заменяет его.

Дополнительные каталоги совместимости и отключённые skills задаются в конфигурации:

```json
{
  "skills": {
    "compat": ["agents", "claude"],
    "disabled": ["unused-skill"]
  }
}
```

Такой `compat` добавляет поиск в `.claude/skills` в проекте и домашнем каталоге.

### Субагенты

Для отдельных задач можно определить помощников в `./.xarness/agents/<имя>.md` или `~/.config/xarness/agents/<имя>.md`. Определение проекта имеет приоритет; встроенных субагентов нет.

Пример `.xarness/agents/reviewer.md`:

```markdown
---
name: reviewer
description: Проверяет код на ошибки без редактирования файлов
tools: [read_file, grep, list_dir, read_symbol]
---
Исследуй указанный код и верни список проблем с пояснениями и путями к файлам.
```

Основной агент вызывает помощника инструментом `agent`. Субагент получает отдельный контекст и возвращает итоговый отчёт. Добавьте объект `agents` на верхний уровень конфигурации, чтобы настроить модель помощника:

```json
{
  "agents": {
    "reviewer": {
      "model": "local/my-model",
      "enabled": true
    }
  }
}
```

Без `model` используется модель вызывающего агента. В объект `reviewer` можно добавить `"think": "off"`, если у модели настроен такой уровень. Необязательный `extra` задаёт JSON-поля запроса поверх выбранного уровня `think`.

По умолчанию последовательные вызовы субагентов в одном ответе выполняются параллельно; доступны и фоновые вызовы. Для сервера с одним слотом задайте `"agents_parallel": false` **на верхнем уровне конфигурации**. `/agents` открывает панель работающих помощников, `/agents list` показывает определения.

## Работа в терминале

| Команда | Действие |
| --- | --- |
| `/model [провайдер/id]` | Показать модели или переключить текущую. |
| `/think [уровень]` | Показать или выбрать уровень рассуждения. |
| `/plan <задача>` | Исследовать проект и предложить план. |
| `/compact [фокус]` | Заменить историю кратким изложением; можно указать, что сохранить. |
| `/clear` | Очистить историю и начать новую сессию. |
| `/resume [n]` | Показать сохранённые сессии или загрузить выбранную. |
| `/map` / `/map show` | Пересобрать карту репозитория / показать её. |
| `/mcp`, `/lsp`, `/skills`, `/agents list` | Посмотреть подключённые расширения. |
| `/agents` | Открыть панель субагентов или переключить её на следующего. |
| `/stats` | Показать статистику. |
| `/help`, `/quit` | Справка / выход. |

`Enter` отправляет сообщение, `Shift+Enter` / `Alt+Enter` / `Ctrl+J` добавляют строку, `Tab` дополняет команды и аргументы. `Esc` прерывает текущий ход или закрывает панель субагентов. Фоновые задачи продолжают работу после прерывания. `PgUp` / `PgDn` и колесо мыши прокручивают диалог; `↑` / `↓` перебирают историю ввода. В запросе подтверждения выберите вариант стрелками или `Tab` и нажмите `Enter`.

Сессии автоматически сохраняются в `./.xarness/sessions/`. Для продолжения последней сессии в том же проекте:

```bash
xarness --continue
# или xarness -c
```

Крупные результаты инструментов сокращаются в контексте, а полные выводы команд сохраняются в `./.xarness/tmp/`; временные файлы очищаются при запуске и `/clear`. Каталоги сессий и временных файлов получают собственный `.gitignore`.

Пути в сообщении дополняются через `@`: `@src/`, `@../billing/`, `@/work/orders/`, `@~/projects/`. Стрелки выбирают вариант, Tab или Enter вставляет его, Esc закрывает подсказки. Для путей с пробелами используются кавычки: `@"my service/"`. При отправке модель получает абсолютные пути без `@`, с раскрытыми `~` и `..`; в журнале остаётся исходная запись. Поиск идёт по текущей папке пути; содержимое файлов автоматически не добавляется.
